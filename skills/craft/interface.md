# Interface design in SMG: flags, launcher, metrics, errors

How SMG shapes what an operator touches: the clap command line in `model_gateway/src/main.rs`, its mirrors in the Python launcher and the Helm chart, the start-up records, the probes, the metric and log names, and the error bodies.
Every rule below is read from SMG `176ce3ae` (v1.13.0); `L` ranges are line numbers at that commit, and a bare sha is a commit in its history since 2026-08-20.

## Designing a flag

1. **Name.** The long flag is the field name with dashes unless `long = ".."` says otherwise; the unit is in the name (`cache_ttl_secs` L524-525, `selection_accounting_ttl_ms` L487-492, `max_buffered_request_bytes` test L4221-4233). A switch that turns a default off is spelled `--disable-...` (`disable_retries` L1362, `disable_circuit_breaker` L1384, `disable_health_check` L1414); a switch that changes a default answer is a positive verb (`--worker-overload-shed`, test L5189-5202). The field's doc comment is its help text (L180-181), and the help names the bound and the opt-out: tests `the_runtime_flag_help_names_the_bound` L5678-5692 and `the_help_names_the_sources_and_hides_the_values` L6409-6441 read `render_long_help` for them.
2. **Group and heading.** The field goes into the group of its responsibility (`RoutingArgs`, `WorkerArgs`, `DiscoveryArgs`, `ServingArgs`, `ModelArgs`, `IntegrationArgs`) flattened into `CliArgs` (L195-207), under the `// ==== Heading ====` comment of its `help_heading` (L212-216): clap prints headings in first-use order and fields in declaration order (L176-181); only the Mesh Server flags carry no heading (L181-182). The groups exist to keep clap's construction on sibling stack frames; one struct overflowed a debug thread stack (L188-193, `35d5d7a0`).
3. **Type and `value_parser`.** A closed set is a `value_parser = [..]` list (`--policy` L331-333, `pd_pairing_mode` L603-612) or a `ValueEnum` (`Backend` L68-85, `DiscoveryProvider` L101-123). A bounded number goes through a parser in `model_gateway/src/cli/value.rs`: `parse_positive_usize` L45-51, `parse_unit_fraction` L60-71 (0.0 excluded because a `>=` threshold of zero vetoes every worker), `parse_usize_in_range` L53-58 behind the job-queue parsers L73-79, or clap's `value_parser!(u64).range(1..)` (L524). A parser's refusal names the value and the shape expected; the API-key parsers name only the shape, since the value is the credential (L1-3, L148-182 with `<redacted>`). Lists: `num_args = 0..` for space-separated values (`--worker-urls` L290, `--prometheus-duration-buckets` L1119-1121), `value_delimiter = ','` with a per-item parser (`--access-log-fields` L1099-1104), `ArgAction::Append` for one value per occurrence (`--control-plane-api-keys` L1771). A trailing optional value clap cannot express (`--prefill URL [port|none]`) is read and stripped before clap by `CommandLine` in `model_gateway/src/cli/url_port.rs` L1-31. A documented `-1` sentinel takes `allow_negative_numbers = true` on a signed type (`--max-concurrent-requests` L1273-1280); a test parses `-1` in the space-separated and `=` spellings and checks an unsigned flag refuses it by name (L3711-3760, `55f87989`).
4. **Default and the disabling zero.** `default_value_t` for typed defaults, `default_value` for strings (L216-220, L331); an `Option` is "unset = off" (`--health-check-port` L226-234). Where zero means off the help says "0 disables" (L463-468, L487-492, L575-579, L1222-1236, L1273-1278), the conversion keeps zero (`connection_timeout_flags_flow_into_router_config` L4306-4318, "zero kept as disabled"), and the start-up line spells it ("HTTP connection timeouts (0 = disabled)", "0 = unlimited", `model_gateway/src/server.rs` L1950-1962). Where zero is meaningless it is refused: at parse time (`cache_ttl_secs_zero_rejected_at_parse` L5370-5372, job queue L4261-4270, overload thresholds L5204-5221) or by the validator with the flag and the opt-out in the reason (`validate_health_check`, `model_gateway/src/config/validation.rs` L2088-2115: "--health-check-interval-secs 0 would probe every worker in a busy loop; --disable-health-check turns probing off"). A budget below one unit is refused, not read as unset (`multimodal_max_inflight_bytes` L826-832). A bool an operator may force either way takes `num_args = 0..=1, default_missing_value = "true"` so `=false` parses (`--remove-unhealthy-workers` L1426-1433).
5. **Environment fallback.** Only two families use clap's `env = ..`: the Oracle `ATP_*` variables (L1579-1632) and the JWT and control-plane keys (L1733-1771), with `hide_env_values = true` on the secret ones (L1596-1601, L1771; test L6409-6420). Every other secret is a `SecretSetting` in `model_gateway/src/cli/secrets.rs`: a flag, an `SMG_*` variable, a `--*-file` flag and an `SMG_*_FILE` variable (L29-61). The flag beats the environment; a value and a file together are refused as "given twice" rather than ranked (L105-114); an empty or multi-line file is refused; a variable set to non-UTF-8 is refused by name (L80-92); no refusal carries a value (L11-14). The resolved source (`flag`, `env`, `file`) is kept for the start-up record (L139-176; `model_gateway/src/main.rs` L1886-1920).
6. **Alias on rename.** A second spelling is a `visible_alias` on the same field (L336-344, L354-360, L365-370, L527-535, L593-601, L1426-1431), listed in the module comment (L182-187); a hidden `alias` is used only for `--model` and `--runtime` (L1453, L1535). `alias_flags_parse_identically_to_canonical` (L4428-4463) parses both spellings into the same `RouterConfig`.
7. **Validation error text.** `ConfigError` has four variants with fixed prefixes (`model_gateway/src/config/mod.rs` L17-33): `InvalidValue { field, value, reason }` prints "Invalid value for field 'port': 0 - Must be > 0" (L21, L56-68), built with `ConfigError::invalid_value(field, value, reason)` (L35-47, `75d17e81`). `field` is the config field in snake_case or a dotted path (`pd_readiness.{role}.min_healthy_workers`, validation.rs L1434-1472); `reason` names the flags and the fix (`validate_distinct_listener_ports` L13-28: "--port and --mesh-port are both 30000; each listener needs its own port"). Shape checks run in `ConfigValidator::validate`, so the CLI, the bindings and a config file get them alike (`2014c230`; a test pins refusal by field name, L2596-2624), and free-standing numeric bounds are one table in `model_gateway/src/config/bounds.rs` L1-11, L18-30. A malformed value is refused by name, never dropped (`malformed_flag_values_are_refused_by_name` L3505-3530, `a219590f`). A flag given without its companion prints `WARNING: ...` on stderr, because the logger is not up yet (`ignored_companions` L2515-2545, L2609-2619; test L3601-3625).
8. **Launcher parity.** `bindings/python/src/smg/router_args.py`: a `RouterArgs` field at its alphabetical place among the keyword-only fields, never at the tail (L1-15); an `add_argument` in the group of the CLI's heading with the same spelling, default and second spelling (L709-791, `--cache-threshold`/`--cache-match-threshold` L929-938); a `_parse_*` mirror of any shaped value (L11-12). `bindings/python/src/lib.rs` L432-435 keeps the PyO3 signature in the same alphabetical order. The procedure is written in `bindings/python/README.md` L114-128.
9. **Helm.** `smg.routerArgs` in `deploy/helm/smg/templates/_helpers.tpl` L219-536 turns values into launcher flags (`router.policy` to `--policy`, L224-225); `router.extraArgs` is the escape hatch (L534-536; `deploy/helm/smg/values.yaml` L230-231). No secret travels in the args: the API key is a mounted file read with `--api-key-file` (L531-532, L540-550), store URLs and Oracle credentials arrive as `SMG_*` and `ATP_*` variables from Secrets (`75055f6c`, `2f6b58ef`). `deploy/helm/smg/values.schema.json` types the values (L1-12).
10. **Docs.** The smg-docs reference `src/lib/content/reference/configuration.md` is hand-written: one table row per flag under the `--help` headings (L1-7), the alias in the row (L106), the env-variable table (L1189-1210) and a "Python Launcher Differences" section (L1015-1026); metric families and the bucket table are in `reference/metrics.md` (L1831-1862). The smg-docs `contributing/development.md` L564 lists the configuration reference as step 8 of a flag's checklist.

## Retiring or renaming a flag

- A rename keeps the field and adds the new spelling as `visible_alias` (L336-344, L1426-1431), the launcher adds it as a further option string of the same option (`router_args.py` L929-938; `test_every_cli_second_spelling_is_a_launcher_option`, `bindings/python/tests/test_cli_parity.py` L298-304), and the docs row says "Alias:" (configuration.md L106).
- A retirement runs in two commits. First the flag is kept but narrowed: `c198820f` (2026-10-15) made `--kv-index` an `Option<String>` whose parser accepts the one surviving value and refuses any other with the reason and "drop --kv-index"; the `--kv-indexer-ttl-secs` and `--kv-indexer-max-entries` prune flags stayed accepted; launcher and binding changed in the same commit. Then `b0d4d21c` (2026-10-26) removed flag, parser, builder setter, config field, validator, binding field, launcher option and the parity exception in one commit (11 files), and a test pins that a launch line still carrying one is refused at parse time as `UnknownArgument` with the flag named, not accepted and ignored (`removed_kv_index_flags_are_refused_at_parse_time`, `model_gateway/src/main.rs` L4194-4215).
- A flag whose job became automatic goes in one commit, launcher option included, and the help of the flag that depended on it is rewritten: `af415423` (2026-08-23) removed the stream-request-bodies-over flag and reworded `stream_body_stall_timeout_secs` (L1222-1228).
- A retired config-file key is refused by name with the replacement knob: `RETIRED_POLICY_INTERVAL_KEY` and the checked `Deserialize` for `PolicyConfig` (`model_gateway/src/config/types.rs` L1576-1598, `3a9ecf3b`). Protocol builders followed the same two steps: deprecated in `da67a609`, removed in `685544cb`.

## Launcher and chart parity

- `bindings/python/tests/test_cli_parity.py` reads `struct CliArgs` and the `cli/` modules from the source tree (L22-29), follows every flattened group and counts the `#[arg]` attributes it reached against the file's total (L99-157, L268-283). It pins: every CLI flag is a launcher option (L290-296), every second spelling too (L298-304), every launcher option is a CLI flag (L306-312), shared literal defaults are equal (L322-341), every option has a `--router-` spelling (L344-357). Divergences live in `CLI_ONLY`, `LAUNCHER_ONLY` and `DEFAULT_DIFFERS` with a reason each, and an entry that no longer holds fails (L33-52, L314-320). On a wheel without the source the tests skip (L6-7).
- `bindings/python/tests/test_router_args_parity.py` pins the dataclass against the PyO3 constructor: every keyword `Router.from_args` passes is a parameter, every parameter is set (L53-80), and the real router builds with no engine behind it (L83-92).
- `bindings/python/tests/test_helm_chart_args.py` pins the chart against the launcher: every `--flag` in `smg.routerArgs` is an exact option (abbreviations off, L1-9, L98-106); no secret-value flag is in the args (L109-114); every `SMG_*`/`ATP_*` variable the chart names is one the launcher reads (L117-125); a store URL renders into the `smg-history` Secret and nowhere else, with a checksum annotation that rolls the pods (L184-207). The render tests need `helm` and skip without it (L82-85).
- Under `smg serve` the launcher embeds `RouterArgs.add_cli_args(parser, use_router_prefix=True, exclude_host_port=True)` (`bindings/python/src/smg/serve.py` L942, L980); `from_cli_args` prefers `--router-<flag>`, falls back to the backend's `--<flag>` unless `--router-disable-arg-fallback` is set (`router_args.py` L793-800, L3135-3160).

## Startup and health

- The authentication posture is named once, before the listener opens (`model_gateway/src/server.rs` L2424-2435): one WARN whose message starts `SECURITY POSTURE` and whose fields name each open surface, its routes and the flag that closes it (`model_gateway/src/server/posture.rs` L1-13, L95-107, L148-231); one INFO `CREDENTIAL SOURCES` with `flag`, `env` or `file` per secret and never a value (L22-40, L69-89). A keyed start logs nothing about posture (tests L461-489).
- Start-up INFO lines carry the bound they announce and spell the zero ("0 = disabled", "0 = unlimited; the admin and probe listeners are outside it", L1950-1962), the bind ("Starting server on {addr}", L1912) and the probe listener with its flag (L1605-1608).
- `/liveness` and `/health` answer 200 `OK` always, while draining included (`model_gateway/src/health.rs` L47-51, L512-517; handlers `model_gateway/src/server.rs` L160-175). `/readiness` answers from a cached snapshot: 200 with `status`, `healthy_workers`, `total_workers`, `models`, and `roles` or `models_without_media_processing` when they apply; 503 with `status: "not ready"` and a `reason` of `draining`, `insufficient healthy workers` or `tokenizer not yet registered` (L455-510). The snapshot is an `ArcSwap` recomputed on worker events and a 1 s checkpoint, so a probe never scans the registry (L7-26, L85-91).
- `--health-check-port` serves the three routes again from a middleware-free router on its own runtime thread; the routes stay on the main listener (L27-35, L639-673; routes L1329-1332 in server.rs).
- Probe logging rule: the handler attaches the `ProbeResponse` extension (`mark_probe`, health.rs L519-526) and `ResponseLogger` logs a marked response at DEBUG, 503 included (`model_gateway/src/middleware/logging.rs` L57-64, L439-444); `ReportedRefusal` does the same for a refusal the router already logged (L66-73, L445-453); otherwise 5xx logs ERROR, 4xx WARN, the rest INFO (L454-469).

## Metrics and logs

- Names start with `smg_`; counters end in `_total`, durations in `_duration_seconds` recorded as `as_secs_f64()` (`smg_http_request_duration_seconds`, `model_gateway/src/observability/metrics.rs` L595-598). Buckets attach by name in `histogram_bucket_overrides` (L1421-1500): `Matcher::Suffix` for `duration_seconds`, `ttft_seconds` and `tpot_seconds` take the request buckets, which `--prometheus-duration-buckets` replaces; any other histogram needs a `Matcher::Full` entry with its own bucket constant (L393-480) or the exporter renders a summary.
- Every family is described in `init_metrics` (L542-545) after the recorder is installed, or `/metrics` has `# TYPE` lines without `# HELP` (L1400-1405); the HELP text names the labels and the counting rule (L603-612). `model_gateway/tests/metrics/metrics_help_text_test.rs` L1-26 fails on an `smg_` family without HELP. Shed, retry and breaker families are published at zero at start-up (`init_startup_series`, `model_gateway/tests/metrics_eager_registration_test.rs` L1-9).
- Labels: `intern_string` only for server-controlled, low-cardinality values such as worker URLs and matched paths, since interned strings are never freed (L25-26, L37-49); a client-controlled value (model id, tool name) goes through `intern_model_label`, a `BoundedLabels` capped at `MAX_MODEL_LABELS` = 1024 beyond which the label reads `other` (`crates/external_router/src/metrics.rs` L23-29, L87-96, L114); fixed values are `&'static str` (`status_code_to_static_str` L316, `method_to_static_str` L350).
- Logs go through `tracing` with a writer thread per sink (`model_gateway/src/observability/logging.rs` L1-16). `RUST_LOG`, when valid, replaces the filter built from the level; otherwise workspace crates (`WORKSPACE_CRATES` L46-70) log at the level and dependencies at WARN (L580-600). Text or JSON (`--log-json`) lines are written by `TextLine`/`JsonLine`, byte-identical to tracing's stock formats (L617-633; `model_gateway/src/observability/log_format.rs` L1-16); color only on a terminal, `NO_COLOR` and `FORCE_COLOR` honoured (L96-115).
- Correlation: one `http_request` span per request with `method`, `path`, `version`, `request_id`, `trace_id`, `status_code`, `latency` in microseconds, plus the `--access-log-fields` written only when selected (`model_gateway/src/middleware/logging.rs` L306-335, L75-80; names are the `AccessLogField` variants in snake_case, `model_gateway/src/config/types.rs` L707-713). The request id is taken from a configured header when it is 1 to 128 visible-ASCII characters, else generated with the endpoint's prefix (`chatcmpl-`, `cmpl-`, `resp-`, `msg_`, `req-`), and echoed as `x-request-id` (`model_gateway/src/middleware/request_id.rs` L1-14, L36-70).

## Errors on the wire

- One builder: `create_error(status, code, message)` in `crates/external_router/src/error.rs` L96-118 writes `{"error": {"type", "code", "message", "param"}}`, the header `X-SMG-Error-Code: <code>`, and a `GatewayErrorCode` extension the HTTP metrics read (L14-34). `type` follows the status: 403 `permission_error`, 429 `rate_limit_error`, 5xx `server_error`, anything else `invalid_request_error` (L120-142). Status-named helpers wrap it (`service_unavailable`, `too_many_requests`, L36-75), re-exported as `routers::error` (`model_gateway/src/routers/mod.rs` L29). Codes are fixed snake_case constants, never client text (`worker_overload_protection_shed`, `model_gateway/src/routers/common/overload.rs` L45-50; `tenant_rate_limit_exceeded`, `model_gateway/src/rate_limit/rejection.rs` L11; `storage_unavailable`, error.rs L84-93).
- A refused body uses the same shape with `param` set to the field and a code read from serde's words (`missing_required_parameter`, `unknown_parameter`, `invalid_value`, `integer_below_min_value`, `invalid_type`), carried as `RejectionCode` for the metric label (`crates/protocols/src/validated.rs` L52-85, L96-115).
- `Retry-After` on every shed: admission sheds send `SHED_RETRY_AFTER_SECS` = 2 (a 408 would read as a transport error and get instant proxy retries; `model_gateway/src/middleware/mod.rs` L53-55, `model_gateway/src/middleware/concurrency.rs` L46-53); the scheduler sends 429 or 503 with 2, and 503 with 1 plus `X-SMG-Preempted` on preemption (`model_gateway/src/middleware/scheduler/error.rs` L25-35); an overload shed is 503 with the load-monitor poll interval, latched once at start-up by `set_shed_retry_after_secs`, and marked non-retryable (overload.rs L40-56, L226-234); the tenant rate limit omits the header when the wait is 0 or impossible (rejection.rs L13-30).
- Messages routes: every 4xx/5xx is reshaped into `{"type":"error","error":{"type","message"},"request_id"}` by `MessagesErrorEnvelopeLayer`, placed outside the other middleware and once more at the edge; status and headers (`Retry-After`, `WWW-Authenticate`, the error-code header) are kept and `error.type` follows the status (`overloaded_error` for 503 and 529, `timeout_error` for 504) (`model_gateway/src/middleware/messages_errors.rs` L1-8, L44-68, L128-136; the type is `ErrorEnvelope`, `crates/protocols/src/messages.rs` L1528-1541).

## Protocol types

- Spelling follows the vendor spec: `#[serde(rename = "type")]` for the reserved word (`crates/protocols/src/messages.rs` L1534), `#[serde(tag = "type", rename_all = "snake_case")]` for tagged unions (L382, L436); another engine's spelling is accepted on input with `#[serde(alias = "reasoning")]` (`crates/protocols/src/chat.rs` L54-57).
- Unknown fields are preserved, not dropped: `#[serde(flatten)] other: Map<String, Value>` closes the request (chat.rs L406-408); provider fields are all-`Option` extension structs flattened into the message (`KimiSystemExt` L32-40; `crates/protocols/src/ext/mod.rs` L1-9), and `retain_if` drops a struct the active profile does not own, reporting it once (L15-45). Where the spec refuses extras, `#[serde(deny_unknown_fields)]` (messages.rs L389-392; `crates/protocols/src/responses.rs` L486-492), with a hand-written `Deserialize` where a flattened map blocks the attribute (responses.rs L533-537).
- `#[serde(default)]` marks what the spec always sends so an upstream's missing key reads as the default (`service_tier` chat.rs L1061-1068; `refusal` and `annotations` with null-as-empty L1086-1096; K3 system content L34-36); `skip_serializing_if` keeps absent fields off the wire (L329-396, L1097-1188).
- Vendor behaviour is a profile, not a core rule: `ProviderProfile::for_model` selects from the model id and the alias registry (`crates/protocols/src/profile/mod.rs` L1-15, L169-180) and runs in `Normalizable::normalize` before validation (chat.rs L895-910), so every handler that extracts with `ValidatedJson` gets deserialize, normalize, validate and the 400 for free (validated.rs L406-449).

## Review questions

1. Is the flag in the right `CliArgs` group under an existing `help_heading`, with its doc comment naming the unit, the bound and the opt-out?
2. Is zero either documented as "disables" and kept through `to_router_config` and `to_server_config`, or refused by name by a parser or the validator?
3. Does the refusal read `Invalid value for field '<field>': <value> - <reason>` with the flag and the fix in the reason, and is `value` redacted when it could be a credential?
4. Did `router_args.py` (alphabetical field, same default and second spelling), `lib.rs` and the parity tests change in the same PR, and does `test_cli_parity.py` pass without a new exception? Is the smg-docs row written?
5. If the chart needs the setting, does `smg.routerArgs` render it as an exact launcher option, and does any secret travel as a mounted file or a Secret-backed variable rather than an argument?
6. For a metric: `smg_` name with `_total` or `_seconds`, described in `init_metrics`, a bucket matcher if it is a histogram off the `duration_seconds` suffix, and client-controlled labels through the bounded interner?
7. For an error: built with `create_error` or `ValidatedJson`'s `rejection`, a fixed snake_case code, `Retry-After` on any shed, and still correct after the Messages envelope reshapes it?
8. For a wire type: spec spelling via `rename`/`rename_all`, `#[serde(default)]` where the spec always sends the field, `flatten` or `deny_unknown_fields` chosen by the spec, and vendor behaviour in a profile?
