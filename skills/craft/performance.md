# Performance discipline in SMG

A hot path is anything that runs per request, per worker-scan, or per streamed token/frame: parse, select, dispatch, per-token decode, SSE framing, metrics. The budget mindset is one allocation, one serialization and one wait per *stream*, not per token, and every buffer, cache and channel bounded by bytes. Paths are relative to the SMG repo root (`smg-docs/` prefix for the docs repo); a commit of `—` means the code was already in tree at the start of the visible history (844d3c0a, 2026-08-20).

## Ownership and cloning

| Rule | Where it is applied | Commit | The anti-pattern |
|---|---|---|---|
| A request's parsed body has one owner for the dispatch phase, `RequestLease<T>`; routing reads it through a borrowed `LeaseView<'_, T>`, and `release_dispatch` frees the parsed request the moment the upstream bytes exist (retries off). | `model_gateway/src/routers/common/request_lease.rs:40-57,162-176` | — | Cloning the parsed request into routing derivatives, or holding it for the whole generation. |
| Serialize once into a buffer pre-sized from the raw length, trim doubling slack, then hand out the one `Bytes` by refcount to each dispatch attempt. | `model_gateway/src/routers/common/mod.rs:73-89,102-110`; `model_gateway/src/routers/common/request_lease.rs:113-128` | 43a4cbe4 | `serde_json::to_vec` per attempt; `Bytes::from(vec)` of a 2x-grown `Vec` kept for the stream's life. |
| Read-mostly request data is shared by `Arc`, cloned by refcount: tool schemas are `Option<Arc<[Tool]>>` across preparation, response spec and reader; route-meta stamps are `Arc<Extensions>` with `Arc::make_mut` on the rare write. | `crates/protocols/src/chat.rs:280,857`; `crates/external_router/src/tenant.rs:57-61,93-100` | 7f515ec8, a7395869, 6fa262fb | `Vec<Tool>` cloned into the spec; `Extensions` cloned with every copy of a request's meta. |
| Streamed text borrows the delta: Symphony events carry `Cow<'d, str>`, `Events::recycle` keeps the event buffer across steps, token spans are byte ranges into the delta, `into_delta_ref` writes the chunk from the borrowed text, and argument fragments borrow too. | `crates/symphony/src/event.rs:1-9,17-22,310-312,556`; `crates/symphony/src/input.rs:22-27`; `crates/symphony/src/tokens.rs:1-13`; `crates/symphony/src/adapt/chat.rs:78-82`; `crates/symphony/src/engine.rs:189` | 7f7293f3, d70e56bf, fee28fc4, 4f1c17e3 | A `String` per event per token; a choice struct that owns a copy of the text before serialization. |
| Decoders append into the caller's buffer (`append_token_into(.., out: &mut String)`, `step_into`, `flush_into`) instead of returning a string per token. | `crates/tokenizer/src/sequence.rs:201`; `crates/tokenizer/src/byte_level.rs:414`; `crates/tokenizer/src/stop.rs:427-443` | 282fa457 | `fn step(..) -> Result<String>` called once per token. |
| A request's context moves into its pipeline future once (`run` boxes once; `run_inner` is an `async move` over `ctx`); the ZMQ arm is `Box::pin`ned at the backend dispatch so gRPC requests are not sized by it (one jemalloc size class, 10,240 -> 12,288 B per request); rare engine payloads ride `Option<Box<..>>`. | `model_gateway/src/routers/grpc/pipeline.rs:650-657,675-680`; `model_gateway/src/routers/grpc/backend_client.rs:270-278`; `crates/engine_zmq_client/src/protocol/vllm/output.rs:91-111` | d0a23a5e, 788a0917, c661c25f | An `async fn` hop that rebinds a 2.6 KiB context in every caller's state machine; an enum whose rare variant sizes every frame. |
| Name lookups on the request path allocate nothing: `eq_ignore_ascii_case` over a static table, a `name_to_id` lookup by `&str`, a case-folded index built once. | `crates/tokenizer/src/registry.rs:273-283`; `crates/symphony/src/formats/registry.rs:297-305,339-367` | 89a61fae, 176ce3ae | `name.trim().to_ascii_lowercase()` per request; a scan of every checkpoint name per request. |
| The lints enforce the small cases: `cloned_instead_of_copied`, `inefficient_to_string`, `assigning_clones`, `trivially_copy_pass_by_ref`, `or_fun_call`, `ref_option`, `large_futures` (threshold 20480 B, so startup builders stay unboxed and runaway futures are caught) are `warn`, and CI runs clippy with `-D warnings`. | `Cargo.toml:124-170`; `clippy.toml:31-36`; `smg-docs/src/lib/content/contributing/code-style.md:47-85` | — | `.cloned()` on `Copy` items; `x = y.clone()` where `clone_from` reuses the allocation; `unwrap_or(expensive())`. |

## Memory bounds (RSS)

| Rule | Where it is applied | Commit | The anti-pattern |
|---|---|---|---|
| Upstream bodies of 1 MiB or more go as one-shot streams with an explicit `Content-Length`, so no layer holds a refcount on the body until response headers arrive. | `model_gateway/src/routers/common/mod.rs:64-71,112-125` | — | `builder.body(bytes)` for large bodies, where reqwest's retry and redirect clones keep the allocation for the whole generation. |
| Worker response bodies are read capped at `max_payload_size` (over: 502 `upstream_response_too_large`); the request body is capped at the edge by `http_body_util::Limited`, with a declared over-limit length refused before any layer runs, and no boxed frame added to responses. | `model_gateway/src/routers/http/router.rs:1135-1170`; `model_gateway/src/middleware/body_limit.rs:1-15` | —, 4731d8d9 | `res.bytes().await` with no cap; `tower_http`'s limit, which boxes `poll_frame` on every streamed response frame. |
| Response channels are bounded (32 frames), so a slow client back-pressures the engine read loop; buffered chat chunks flush at 16 KiB; an unterminated SSE frame over 1 MiB is forwarded as it comes. | `crates/external_router/src/sse.rs:485-493`; `model_gateway/src/routers/http/router.rs:1694-1698`; `model_gateway/src/routers/grpc/regular/streaming/frames.rs:19-21`; `model_gateway/src/routers/common/sse_rechunk.rs:66-67` | —, a311ab56 | `mpsc::unbounded_channel` for a response body: a stalled client drives the gateway to OOM. |
| Caches are bounded by bytes, not only by entry count: the L0 exact-match cache has an entry cap and a byte budget (an input over a quarter of it is not cached; eviction is sampled LRU over 8 keys), the pixel cache is an `LruCache` with `max_bytes` and heap-byte accounting; tracking maps carry hard caps. | `crates/tokenizer/src/cache/l0.rs:1-26`; `crates/tokenizer/src/cache/mod.rs:52-54`; `model_gateway/src/routers/grpc/multimodal/pixel_cache.rs:72-86`; `model_gateway/src/policies/cost/accounting.rs:51-53`; `model_gateway/src/policies/round_robin.rs:19`; `model_gateway/src/mesh/adapters/worker_sync.rs:93` | b7fa7dce, — | An entry-count cache that happily holds 128k-token prompts; a map keyed by client-controlled strings with no cap. |
| The selection snapshot copies the prompt text only when a configured policy will read it (`keep_text`); the registry answers that from a `TextNeeds` byte recomputed where policies change, not per request. | `model_gateway/src/routers/grpc/common/stages/worker_selection.rs:373-378`; `model_gateway/src/policies/registry.rs:60-118` | e86b4000, 91dd0a77 | Copying the prompt text next to the token ids for every request. |
| jemalloc is the global allocator with `background_thread:true,dirty_decay_ms:10000,muzzy_decay_ms:0,narenas:16`: stock settings left ~1.5 GB resident over ~270 MB live after a burst (soak s2), and 16 arenas cut slabs from 1.6 GB to 0.4 GB at the same CPU per request. | `model_gateway/src/main.rs:5-24`; `model_gateway/src/observability/metrics.rs:499-524` | 152e6574 | glibc malloc; jemalloc's default of four arenas per CPU with ~240 threads each on its own arena. |
| Every call to a remote history store is bounded by `op_timeout_secs`; the memory store updates a record in place with `Arc::make_mut` and chains are read in place. | `crates/data_connector/src/bounded.rs:1-16`; `crates/data_connector/src/memory.rs:858-870` | af59ba47, b2d89254 | A frozen store holding every request that touched it; cloning the response chain out of the store on every turn. |
| The KV chain index keeps run headers, hash arrays and child tables in one word arena with per-class free lists and generation-tagged ids; a split shares the hash array instead of copying it; readers allocate nothing but the result map. | `crates/kv_index/src/chain_index.rs:1-2,22-40`; `crates/kv_index/src/chain_index/arena.rs:1-3`; `crates/kv_index/src/lane_map.rs:1-11` | fad0f553, b58d49f0 | A tree of heap-allocated nodes behind `Arc`, one allocation per block. |

## Locks and concurrency

| Rule | Where it is applied | Commit | The anti-pattern |
|---|---|---|---|
| State read per request and written rarely is an `ArcSwap` snapshot (8 files): the router map, the registry's `global_routing_snapshot` (rebuilt lazily, once per registration storm), a worker's runtime and breaker, cache-aware pool tables; load reports are published as immutable snapshots and a reader takes one `Arc` clone. | `model_gateway/src/routers/gateway.rs:107-108`; `model_gateway/src/worker/registry.rs:296-321`; `model_gateway/src/worker/basic.rs:1282-1283`; `model_gateway/src/policies/cache_aware.rs:229`; `model_gateway/src/worker/load_state.rs:1-16` | bd83e8e1, 64c8763e, b5fa3689 | `RwLock<HashMap<..>>` read on every request; copying the worker map per request. |
| Concurrent maps are `DashMap` (22 files), never a bare `HashMap` behind a mutex; a live count is a separate `AtomicUsize`, because `DashMap::len()` locks every shard. | `model_gateway/src/policies/registry.rs:119-134`; `model_gateway/src/observability/inflight_tracker.rs:26-34`; `REVIEW.md:37` | —, bd83e8e1 | `Mutex<HashMap>` for the worker registry; `DashMap::len()` on the request path. |
| Short synchronous sections use `parking_lot` (30 files, against 2 with tokio locks): the scheduler queue is a contention point so it is a `parking_lot::Mutex`, not an async mutex; per-class in-flight counts are packed in one `AtomicU64` claimed by one CAS; TTFT and preemption share one `AtomicU64` with a sentinel. | `model_gateway/src/middleware/scheduler/queue.rs:53-60`; `model_gateway/src/middleware/scheduler/slots.rs:1-10`; `model_gateway/src/middleware/scheduler/inflight.rs:13-24` | — | `tokio::sync::Mutex` around a sub-microsecond section; a per-class counter array with a check-then-claim race. |
| Nothing O(workers) runs under a shard guard: placement-index inner maps are `Arc`'d so a cloned handle is walked without the outer guard; selection reads status, load and veto per worker under one `ArcSwap` guard; the hash ring rebuild clones the copy-on-write slice out first, serializes under its own mutex and rehashes only changed URLs. | `model_gateway/src/policies/cache_aware.rs:268-273,1588-1592`; `model_gateway/src/worker/registry.rs:2118-2165` | 5bf7c80c, 64c8763e, bfa92a0b | Hashing or scanning while holding a `DashMap` shard; a full ring rebuild per registration, quadratic over a wave. |
| Verdicts are latched when the data arrives and read per request: the overload predicate runs once per ingested load report (O(DP ranks)) and is latched into routing state; a token within the stamped millisecond records no new progress. | `model_gateway/src/worker/overload.rs:1-10,110-129`; `model_gateway/src/worker/runtime.rs:691-696` | —, 7d139e99 | Re-evaluating thresholds per request; an atomic store and a wake per token. |
| A wait is registered once per stream, not per chunk: the relays pin `client_gone = tx.closed()` outside the loop; `WatchedStream` keeps one `client_gone` future for the stream's life. | `model_gateway/src/routers/http/router.rs:1719-1720,1750`; `model_gateway/src/routers/http/stream_relay.rs:138-142,238`; `model_gateway/src/routers/grpc/proto_wrapper.rs:977-998` | 2ba8d95b, 0807a1ba | `tx.closed()` built inside `select!` per chunk, registering and dropping a waiter on every frame. |
| Log lines go to writer threads through a bounded, lossy channel and are written in batches (5 ms window, 64 KiB); runtime threads never wait on the sink. | `model_gateway/src/observability/logging.rs:1-16,215-220` | bd83e8e1, 10b89d3d | A synchronous `std::io::stdout()` writer parking a runtime worker on every access-log line under writeback pressure. |

## CPU on the hot path

| Rule | Where it is applied | Commit | The anti-pattern |
|---|---|---|---|
| Per-stream invariants are serialized once: `ChatChunkFrame` renders the `id`/`object`/`created`/`model` head once and copies it in front of each chunk; chunks are appended to one `BytesMut` and flushed at 16 KiB after draining the engine's ready chunks; Messages SSE is formatted into a reusable buffer. | `model_gateway/src/routers/grpc/regular/streaming/frames.rs:19-70`; `model_gateway/src/routers/grpc/regular/streaming.rs:1344-1365,1452-1470` | fbfd07ad, afb5e659, a311ab56 | Building a chunk struct and `serde_json::to_vec` per token, one channel send per token. |
| Metric handles are kept per thread per worker (`ByWorker<V>`, dropped when the worker set changes) and gauges are set through them, not through a key built per call; labels are interned to `Arc<str>` and only low-cardinality, server-controlled strings are interned. | `model_gateway/src/observability/metrics.rs:25-48,55-58,105-146,187-190` | e14b16ce, d39b4207, 2932886d, 3284bc21 | `counter!("name", "worker" => url.to_string())` per request; interning user-controlled labels. |
| Indexes replace scans: a pre-computed hash ring per model (O(log n) lookup, rebuilt on membership change), the model index as an `Arc<[T]>` snapshot, the `TextNeeds` byte, the case-folded format index. | `model_gateway/src/policies/consistent_hashing.rs:9-14,87-90`; `model_gateway/src/policies/mod.rs:395-397`; `model_gateway/src/worker/registry.rs:1-13` | —, 91dd0a77, 176ce3ae | Building a ring per request; `workers.iter().find(|w| w.url == url)` per request (the example in `smg-docs/src/lib/content/contributing/code-style.md:404-412`). |

## Measuring and gating

- **Criterion benches**: six `benches/` directories; the gateway declares 17 `[[bench]]` targets (`request_processing`, `tokenizer_benchmark`, `sse_rechunk`, `access_log`, `policy_selection`, `kv_index_decision`, `scheduler_admission`, `routing_allocation_bench`, `sync_alloc_bench`, ...) in `model_gateway/Cargo.toml:205-286`; the crates add `crates/kv_index/benches` (`churn.rs`, `match_insert.rs`, `throughput_bench.rs`, `mooncake_replay/`), `crates/tokenizer/benches` (`incremental_decode.rs`, `stop_decoder.rs`, `prefix_cache.rs`, `encode_cost.rs`, ...), `crates/symphony/benches/throughput.rs`, `crates/multimodal/benches`, `crates/engine_servicer/benches`. The `[profile.bench]` is opt-level 3 (`Cargo.toml:290-293`).
- **The PR gate**: `.github/workflows/benchmark-request-processing.yml:60-91` and `.github/workflows/benchmark-tokenizer.yml:64-74` build the base branch's and the PR's bench binary in one checkout and run them interleaved through `scripts/bench_gate.py` (doc at lines 1-36; tests in `scripts/tests/test_bench_gate.py:115-150`). An id fails only when the median change is worse than its threshold *and* the runs do not overlap (the slowest base run is faster than the fastest PR run; chance 1/C(2N,N), one in 20 at N=3). Beyond the threshold with overlap is "suspect", not failed; a gated id missing from the PR fails. Thresholds and the measured spreads that justify them live in `.github/bench-gates/request-processing.toml` (`repeats = 3`, 15 % for `json_serialization|json_deserialization|bootstrap_injection|full_round_trip`, identical-build spread 1.5-6.4 %) and `.github/bench-gates/tokenizer.toml` (10 % encode and latency groups and `decode_stream`, 20 % `direct_decode`, 25 % `sequence_decode` and `stop_sequences/no_stops`, 15 % `with_stops`; rule: the smallest multiple of 5 % at least twice the identical-build spread and 1.5x the across-build spread, never under 10 %). `benchmark-manual-policy.yml`, `benchmark-radix-tree.yml` and `benchmark-tool-parser.yml` run weekly (`0 0 * * 0`) and upload results without a gate.
- **CPU-only stress bed** (`scripts/bench/grpc_stress/`, nightly in `.github/workflows/nightly-grpc-stress.yml:36-56,69-79`): the release gateway with `cache_aware` and KV events in front of 12 `mock-worker --engine realistic` gRPC engines, driven by the `stress_load` binary of `crates/mock_worker`. Families: `unary` 1k/3k/5k req/s, `stream` 500/1,500 SSE streams/s, `idle` 10,000 open streams held 30 s (memory per open stream, shedding at the default admission bound), `long` 32k/128k-token prompts, `image`, `tenants`, `tools`, `responses`. `sample.py` (lines 2-4, 18-32) samples CPU, anon/file RSS, cgroup memory and the allocator gauges each second; `report.py` (lines 4-5, 30) prints CPU ms/request, us/frame, latency percentiles, anon RSS start/end with its slope in MB/min (a leak is a slope), peak RSS and jemalloc live bytes; `perf_sites.py` folds `perf script` into the share of cycles in the allocator, memcpy and `Clone` impls and the sites behind them; `heap_sites.py` diffs two heap profiles into allocation sites. No pass/fail threshold: compare a change against `main` through the same cells on the same host, interleaved (README).
- **GPU nightly**: `.github/workflows/nightly-benchmark-amd.yml:13-14` runs `e2e_test/benchmarks/test_nightly_perf.py` with genai-bench on Sundays; it states "No performance thresholds — results are uploaded" (lines 3-4).
- **Local rigs**: `scripts/scale_test.sh:1-7` (N mock HTTP/gRPC workers in one process, REST-registered, the gateway's own PID sampled for CPU and `/health` latency), `scripts/sim_ab.sh:1-9` with `scripts/sim_load.py` (routing-policy A/B against realistic mock engines, TTFT/ITL/E2E/throughput side by side), `scripts/scale_load.py`; the mock worker is `crates/mock_worker/src/main.rs:1-7`.
- **Allocator telemetry and profiles**: gauges `smg_allocator_{allocated,active,resident,metadata}_bytes` (`model_gateway/src/observability/metrics.rs:1539-1551`, covered by `model_gateway/tests/allocator_metrics_test.rs:20-44`); `POST /heap_profile` dumps a jemalloc `prof.dump` into `--jemalloc-prof-dir` on a binary built with `--features jemalloc-profiling` and started with `_RJEM_MALLOC_CONF=prof:true,prof_active:true,lg_prof_sample:19`, 501 otherwise (`model_gateway/src/observability/heap_profile.rs:1-8`, route `model_gateway/src/server.rs:825-828`, `model_gateway/tests/heap_profile_test.rs:1-2`). Profiles read with `jeprof`; CPU profiles need `strip = false` (`Cargo.toml:193`) and, for the stress bed, `-C force-frame-pointers=yes` with line tables (`scripts/bench/grpc_stress/README.md`).
- **The commit carries the number**: the perf commits and the comments they leave quote the measurement (10,240 -> 12,288 B per request in `model_gateway/src/routers/grpc/backend_client.rs:270-278`; 1.6 GB -> 0.4 GB of slabs in `model_gateway/src/observability/metrics.rs:499-524`; half the CPU per request at opt-level 3 in `Cargo.toml:184-189`).

## Review questions

1. Does the change clone, allocate, serialize or `send` per token or per chunk? Could it borrow the delta (`Cow<'d, str>`), append into the caller's buffer, or render the invariant once per stream? (`REVIEW.md:35`)
2. Where does the request body's memory end? Does the parsed request still die at `release_dispatch`, or does a new `Arc` or clone keep it alive across the generation?
3. Is every new buffer, channel, cache or map bounded, by bytes where entries vary in size, and what happens at the bound (back-pressure, 413/502, eviction)?
4. Is new shared state read per request? Then it is an `ArcSwap` snapshot or a `DashMap`, not `RwLock<HashMap>`, and nothing O(workers) runs under a guard. (`REVIEW.md:37`)
5. Is this computation really per request, or per worker, per policy change, per load report or per stream, where it can be latched, kept as a handle, or built once as an index?
6. Does the future grow? A new awaited branch in the pipeline or a dispatch arm sizes every request's future; box the rare large arm (`large_futures`, threshold 20480 B).
7. Which benchmark covers the path, is it in a gated group (`request_processing`, `tokenizer_benchmark`), and if not, which stress-bed family would show the change in CPU per frame or RSS slope?
8. Was it measured, and is the number in the commit message or a comment at the site, as the perf commits do?
