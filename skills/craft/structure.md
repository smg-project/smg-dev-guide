# Structure and duplication in SMG

How SMG (verified at `176ce3ae`, v1.13.0) keeps one spelling per fact, one copy per mechanism, and a predictable place for code and tests.
Every row cites the file and lines it was read from; line numbers drift, names less so. Sibling guide: `code-style.md` in smg-docs (`src/lib/content/contributing/`).

## Spell it once

| Idiom | Where (path:line) | What breaks if you copy instead |
|---|---|---|
| A Symphony table is one row of the `tables!` list: variant, doc, operator name, builder. The macro writes both the `Table` enum and `ROWS` from it. | `crates/symphony/src/formats/registry.rs`:45-64 (macro), 67-142 (the list), 159-183 (`Table::ALL`, `name`, `named` read `ROWS` by `self as usize`) | A variant without a row changes `ROWS`'s length and the index arithmetic, so it does not compile; tests at 618 and 666 pin that every table spells its name back and stands at its own index. |
| A checkpoint group is one line of `groups.json`; `build.rs` writes it as `const GROUPS` and the registry includes it. | `crates/symphony/build.rs`:3-45; `crates/symphony/src/formats/registry.rs`:290-295 (`include!`), 279-287 (a group naming an unknown table panics at compile time), test 414 (one group per line) | A group spelled in Rust as well as JSON diverges silently; the README's models table is written from `GROUPS` by `crates/symphony/tests/readme.rs`:1-5 and the test fails on a stale table. |
| The Python launcher's options are read off `struct CliArgs` in the Rust source, not retyped. | `bindings/python/tests/test_cli_parity.py`:1-11 (reads `model_gateway/src/main.rs` and `model_gateway/src/cli/`); `bindings/python/tests/test_router_args_parity.py`:1-9 (dataclass fields vs the Rust constructor); `bindings/python/tests/test_helm_chart_args.py`:1-14 (every chart `--flag` is an exact `RouterArgs` option, no secret in args) | A flag added on one side fails the test, not a launch; the exception lists carry a reason per entry and an entry that no longer holds fails too, so the lists cannot rot. |
| Legacy parser names map to tables in one array, and the names no table answers to are listed with reasons. | `model_gateway/src/routers/grpc/utils/aliases.rs`:36 (`ALIASES`), 63 (`UNANSWERED`), tests 128 and 156 | An alias that is also a table's own name, or a name in neither list, fails the test: every name of the two legacy registries is accounted for. |
| Closed enums, every arm written, no `_ =>`. | `ZmqDialect`: `crates/engine_zmq_adapter/src/client.rs`:97-112 ("a closed set ... no unreachable arm"), matches at 77-82, 368-381, `model_gateway/src/routers/grpc/backend_client.rs`:425. `BackendClient`: `backend_client.rs`:44-47; one-arm sites use `let ... else` or `matches!` (`model_gateway/src/worker/rl_adapter.rs`:182). `ProviderType`: `crates/protocols/src/worker.rs`:316-333, `as_str` 338-345 | A new engine or provider fails to compile at every dispatch site instead of falling into a wildcard that does the wrong thing at runtime. |
| A provider router's id, `--backend` name, label, Cargo feature, `compiled` flag and builder are one `ExternalRouterSpec` constant, present whether or not the build carries it. | `crates/external_router/src/router.rs`:148-165 (struct), 196-235 (`known`: `OPENAI`, `ANTHROPIC`, `GEMINI` with `compiled: cfg!(feature = ...)`), 237 (`all()`); the gateway's refusal names the feature (`model_gateway/src/routers/provider_support.rs`:172) | Admission and dispatch would resolve a provider two ways; a build without the router could not say which feature to enable. |
| Worker placement, PD failure vocabulary and retry live once under `routers/common`, not per router family. | `model_gateway/src/routers/common/placement.rs`:1-9 ("every family used to carry its own copy ... written once"); `model_gateway/src/routers/common/mod.rs`:23-42 | The HTTP and gRPC families drift on pool narrowing, retry and failure naming, which `REVIEW.md`:44 flags as the two code paths that must keep one contract. |
| Lints are silenced with `#[expect(lint, reason = "...")]`, never `#[allow]`. | `Cargo.toml`:141-142 (`allow_attributes` warns, and CI runs `-D warnings`); example `crates/symphony/src/formats/registry.rs`:279-287; 1038 `#[expect` vs 16 `#[allow` sites, all in tests, benches or `model_gateway/test_harness` | An `#[allow]` outlives the code it covered; an unfulfilled `#[expect]` warns, so a stale suppression fails CI and goes (`code-style.md`:85-86). |
| HTTP clients come from one factory per crate. | `clippy.toml`:12-26 disallows `reqwest::Client::new` and its siblings, naming the factories (the gateway's `clients` module, the auth and MCP crates' own, a test binary's helper) | A client built elsewhere panics at build time without the process TLS provider the factory installs. |

## Share the machinery

| Idiom | Where (path:line) | What breaks if you copy instead |
|---|---|---|
| Each gRPC engine client invokes `impl_engine_client_basics` once (connect, trace injector, health, model and server info), then adds its own RPCs. Companions: `impl_get_tokenizer`, `impl_admin_ops`, `impl_subscribe_kv_events`, `impl_abort_for_drop_with_reason`. | `crates/grpc_client/src/lib.rs`:65, 139, 205, 305, 402; invoked in `vllm_engine.rs`:38, `sglang_scheduler.rs`:47, `tokenspeed_scheduler.rs`:52, `trtllm_service.rs`:55, `mlx_engine.rs`:34 | Five hand-written connect paths; a change to the trace injector or channel settings lands in four of them. |
| One gRPC pipeline constructor over `Endpoint` and `Mode`; stages shared by every endpoint sit in `common/stages`, endpoint-specific ones in `regular/stages/<endpoint>/`. | `model_gateway/src/routers/grpc/pipeline.rs`:99-108 (`Endpoint`, 8 variants), 323 (`build(endpoint, mode, deps)`); `model_gateway/src/routers/grpc/mode.rs`:10-14 (Regular, PrefillDecode, EncodePrefillDecode); `model_gateway/src/routers/grpc/common/stages/mod.rs`:1-52 (`PipelineStage`, `BuildStage`, `ProcessStage`) | 24 pipelines by hand. The chat and Messages builders share `model_gateway/src/routers/grpc/regular/stages/backed_plan.rs` (`21e670b1`). |
| History storage backends are wrapped, not edited: hooks and timeouts are decorators over the three storage traits, applied by the factory. | `crates/data_connector/src/hooked.rs`:1-5; `crates/data_connector/src/bounded.rs`:1-17 ("a method added to a storage trait is forwarded here too"); `crates/data_connector/src/factory.rs`:218-247 | A timeout or hook written inside one backend is missing from the others; a new trait method bypasses both wrappers unless they forward it. |
| One conformance scenario runs on every backend: memory always, Redis, Postgres, Oracle when their URL is set. | `crates/data_connector/tests/conformance.rs`:1-13, 211-280 | A backend that passes its own suite but answers an echoed item differently from the others. |
| The gateway re-exports the router glue from `smg-external-router` at its old paths, so callers did not move when the code did. | `model_gateway/src/routers/common/mod.rs`:49-60 (`pub use smg_external_router::{header_utils, mcp_utils, openai_bridge, persistence_utils, realtime, retry, sse, sglang_fields}`); `crates/external_router/src/lib.rs`:8-9 | A second copy of SSE, retry or MCP glue in the gateway, or a mass rename of every import for a crate extraction. |
| Test support is a crate or a gated module, never pasted fixtures. | `model_gateway/test_harness/src/lib.rs`:4-18 (mock and scripted workers, scripted tokenizer, test app, certs), `model_gateway/Cargo.toml`:161-169 (self dev-dependency with `test-util`, harness "compiled once"); 8 `test_support.rs` modules under `#[cfg(test)]` or `#[cfg(any(test, feature = "test-util"))]` (`model_gateway/src/lib.rs`:39-40); `crates/mock_worker/src/lib.rs`:1-2 (one library for the binary and in-process tests) | Mock workers that differ per test binary; fixtures compiled once per binary; the `self-hosted` lint configuration stops meaning anything if default features leak into test targets (`model_gateway/Cargo.toml`:162-165). |
| The ZMQ engine translation is one crate with two consumers: the gateway's direct lane and the Rust servicer. | `crates/engine_zmq_adapter/src/lib.rs`:1-16 ("Neither owns the translation; this crate does"); `11587f14` moved the admin calls' wait rules there; `crates/engine_servicer/src/engine_link.rs` links all three wires (`09998429`) | Two translations of the same wire that disagree on EOS, `max_tokens` or fan-out. |
| Two radix trees intern tenants through one pool. | `crates/kv_index/src/common.rs`:15-27 (`TENANT_INTERN_POOL`, `intern_tenant`; `b3ca2bd9`) | Two `Arc<str>` per tenant name, pointer equality broken across trees. |

## Where code and tests go

- Module item order: imports, constants, types, inherent `impl`, trait `impl`, tests last (`code-style.md`:144-186). `model_gateway/src/policies/round_robin.rs` follows it: `use` 3-14, `const` 19, struct 45, `impl` 51, trait impl 112, `#[cfg(test)] mod tests` 141-142.
- Unit tests sit in `#[cfg(test)] mod tests` at the bottom of the file they test (`code-style.md`:322-324; 769 files). When they outgrow the module, they move to a sibling file, not a second module in the same file: `mod tests;` plus `<module>/tests.rs` (24 files, e.g. `model_gateway/src/policies/cache_aware.rs`:3554 and `model_gateway/src/policies/cache_aware/tests.rs`), or topic-named siblings (`model_gateway/src/routers/grpc/regular/streaming.rs`:4911-4935 declares 12 `#[cfg(test)] mod *_tests;` files beside an inline `mod tests` at 4938). `d48a9dbc` moved 979 test lines out of `model_gateway/src/worker/monitor.rs` into `worker/monitor/worker_monitor_tests.rs`.
- Integration tests: a `tests/` directory per crate (17 crates). The gateway groups them: `model_gateway/tests/<group>_tests.rs` is the binary (`pub use smg_test_harness as common; mod <group>;`, `model_gateway/tests/grpc_tests.rs`:1-6) and `model_gateway/tests/<group>/mod.rs` lists one `mod` per case file; 14 groups. A helper two binaries share is pulled in by path (`model_gateway/tests/startup_tests.rs`:4-5, `#[path = "common/gateway_launch.rs"]`). Nested test modules group cases (`code-style.md`:322-343); test names state the behaviour (`code-style.md`:345-363; `aliases.rs`:128).
- CI shards: every workspace package is tested by exactly one shard and gateway test binaries are dealt round-robin by name (`scripts/ci_rust_tests.sh`:16-25); a new crate without a shard row fails `ci_rust_tests.sh check` (256-290).
- One file per thing: Symphony has one module per table, named after the model family (`crates/symphony/src/formats/mod.rs`:1-2), plus `registry.rs` and `groups.json`. gRPC clients: one file per engine (`vllm_engine.rs`, `sglang_scheduler.rs`, `tokenspeed_scheduler.rs`, `trtllm_service.rs`, `mlx_engine.rs`) beside shared `channel.rs`, `codec.rs`, `abort_on_drop.rs`. History stores: flat files `memory.rs`, `noop.rs`, `oracle.rs`, `postgres.rs`, `redis.rs` with a `<backend>_migrations.rs` each, shared `core.rs`, `factory.rs`, `hooked.rs`, `bounded.rs` (`crates/data_connector/src/lib.rs`:15-30). Servicer and ZMQ protocol: one directory per engine (`crates/engine_servicer/src/{vllm,sglang,tokenspeed,trtllm}/` each with `engine.rs`, `service.rs`, `tests.rs`; `crates/engine_zmq_client/src/protocol/{vllm,sglang,tokenspeed,trtllm}/`). Legacy parsers: one file per parser under `crates/tool_parser/src/parsers/` and `crates/reasoning_parser/src/parsers/`.
- Code moves to the module that owns it, not the crate root: `964e14d6` (`model_gateway/src/mesh/discovery/`), `0ee3ce2e` (RL registry view under `worker/`), `db5f84e6` (`model_gateway/src/server/tls.rs`), `2027d48d` (`worker/worker.rs` became `model_gateway/src/worker/basic.rs`, dropping a module-inception expectation).

## Splitting and size

- The 15 largest `.rs` files at `176ce3ae`: `model_gateway/src/routers/http/pd_router.rs` 7191, `crates/multimodal/src/media.rs` 6564, `model_gateway/src/routers/grpc/common/stages/worker_selection.rs` 6503, `model_gateway/src/main.rs` 6442, `model_gateway/src/routers/grpc/pipeline.rs` 6419, `model_gateway/src/routers/http/router.rs` 6009, `model_gateway/src/routers/grpc/common/stages/request_execution.rs` 5328, `model_gateway/src/config/validation.rs` 5290, `model_gateway/src/routers/grpc/regular/streaming.rs` 5229, `crates/symphony/src/grammar.rs` 5073, `crates/engine_servicer/src/vllm/tests.rs` 5029, `crates/protocols/src/responses.rs` 4919, `crates/tokenizer/src/chat_template.rs` 4870, `crates/protocols/tests/protocol/responses.rs` 4844, `model_gateway/src/policies/cache_aware/tests.rs` 4729.
- Most of that is inline tests: `pd_router.rs` is production to line 2840 and tests after; `pipeline.rs` to 1731 (six test modules follow); `worker_selection.rs` to 2158; `media.rs` carries twelve test modules, one a sibling file, from line 929; `validation.rs` to 2337; `main.rs` to 3299. The production halves are 1.7k to 4.3k lines.
- Since 2026-08-20 (`732a42bf`) the production halves grew (pd_router 2182 to 2841, worker_selection 744 to 2159, main 2110 to 3300, validation 1187 to 2338) and the tests grew faster (pd_router 697 to 4350, worker_selection 450 to 4344, main 658 to 3142). None of the four biggest production bodies was split.
- 255 of the 2050 commits since then are `refactor(...)`. A sample of twelve and what moved them:
  - A nameable concern leaves a growing file for its own module, with the parent keeping a `mod`: `236de80c` (937 lines of request wrappers into `model_gateway/src/routers/grpc/proto_wrapper/request.rs`), `e0b17ffd` (SSE frames into `model_gateway/src/routers/grpc/regular/streaming/frames.rs`), `0474fbde` (`model_gateway/src/worker/metadata.rs`), `1ee8f1fb`, `e9fd2ddd`, `89aed660` (`main.rs` hand parsers, value parsers and secrets into `model_gateway/src/cli/{url_port,value,secrets}.rs`), `db5f84e6` (one `tls.rs` with two concerns, split between `clients/` and `server/`).
  - Tests leave the production module: `d48a9dbc` (979 lines).
  - Two copies become one: `21e670b1` (`backed_plan.rs`, 217 lines removed from two builders), `b3ca2bd9` (tenant pool), `09998429` (`engine_link.rs`), `11587f14` (adapter `admin.rs`), `1aa11f9b` (cache-aware default knobs written once, 227 lines net gone), `dd805831` (the PD HTTP router's three dispatch bodies share their setup and failure answers).
  - Dead code goes once the compiler proves it, and the whole-file dead-code allowances that hid it go with it: `0c4ba5e8` (236 lines), `05507950` (21 uncalled functions), `4ddd66b1`, `9808807b`, `ed76cbd2`.
  - Vocabulary is renamed across the tree in one commit, not file by file: `5eea9545`, `9f883c2c`, `dff19c8a` (role, side and pool).
- Reading: a file is split when a concern has a name or when tests crowd the module, never for line count alone. Expect a reviewer to ask what the new module is called, not how long the old file was.

## Errors and fallbacks

- One `thiserror` enum per domain, no shared error type. The history store has one per storage trait: `ConversationStorageError`, `ConversationItemStorageError`, `ResponseStorageError` (`crates/data_connector/src/core.rs`:167, 332, 635), each with `Timeout`, `Unavailable` and `Rejected` variants that the wrappers and the HTTP mapping read by name (175-191). 62 `pub enum ...Error` across the workspace; the only one named plain `Error` is crate-local (`crates/engine_zmq_client/src/error.rs`:13).
- Config errors are `ConfigError` (`model_gateway/src/config/mod.rs`:16-33) built through one constructor, `invalid_value` (`75d17e81`). `ConfigValidator::validate` (`model_gateway/src/config/validation.rs`:383-456) runs every rule and returns the first error: an Oracle backend without an `oracle` section is `MissingRequired` (424-427); Redis and Postgres bounds run here on every start-up because the Python bindings and a directly built `RouterConfig` never pass through clap (431-452).
- `anyhow` is a boundary tool, not the error type: 9 manifests depend on it against 17 on `thiserror`. In the gateway it is confined to multimodal assembly (`model_gateway/src/routers/grpc/multimodal/`, `common/stages/encode.rs`, `worker_selection.rs`) and converted once, `assembly_error_response` (`model_gateway/src/routers/grpc/multimodal/mod.rs`:112-118), into a typed HTTP error. Context is attached lazily with `with_context` (`code-style.md`:239-251; `model_gateway/src/routers/grpc/multimodal/config.rs`:219-227).
- No silent fallback: `REVIEW.md`:38 lists "silent fallbacks to `None`/default when config validation should fail loudly" as a review item, and the review skill's anti-patterns table names the case where an invariant lives only in a clap `value_parser` (the bindings bypass it). Fixes refuse by name: `6c8004b0` (a negative frame count "refused by name, not as an overflow"), `dfa8222f`, `67782e95` (a timeout that "no longer time[s] out as silent").
- Panics: `unwrap_used` is denied, `expect_used` and `panic` warn under `-D warnings` and need a reason (`Cargo.toml`:125-129; `code-style.md`:253-266); tests are exempt (`clippy.toml`:2-4); `todo!` and `unimplemented!` are disallowed macros (`clippy.toml`:7-10).

## Feature gates

- One Cargo feature per built-in provider router, default none: `crates/external_router/Cargo.toml`:16-21 (`openai`, `anthropic`, `gemini`). The gateway forwards them as `provider-openai`, `provider-anthropic`, `provider-gemini`, bundles them as `providers` in its default set, and keeps `test-util` for its own tests (`model_gateway/Cargo.toml`:18-41).
- The `cfg` lives in the router crate, in pairs: `crates/external_router/src/lib.rs`:12-22 gates the three modules; `crates/external_router/src/router.rs`:256-300 gives every `*_build` a `#[cfg(feature)]` body and a `#[cfg(not(feature))]` twin that returns `not_compiled()`. The gateway has no `cfg(feature = "provider-...")` of its own; it reads `compiled` off the spec. The harness gates its mock OpenAI server the same way (`model_gateway/test_harness/Cargo.toml`:9-11).
- The gateway's self dev-dependency sets `default-features = false` so a `--no-default-features` test run is one (`model_gateway/Cargo.toml`:161-166).
- Four lint configurations keep every combination compiling (`scripts/ci_rust_tests.sh`:216-236, run from the matrix in `.github/workflows/pr-test-rust.yml`:359): `all-features` (clippy with every feature, then rustdoc under `-D warnings`), `self-hosted` (`--no-default-features` plus `grpc-client`, `jemalloc-stats`), `anthropic-only`, `default-build` (`llm-multimodal` with and without `hf-hub`, the Python and Go bindings). Other opt-ins follow the pattern: `crates/multimodal/Cargo.toml`:18-23 (`hf-hub` default, `opencv-video` off).

## Review questions

1. Is the new table, group, alias, flag or provider spelled in the one place the other surfaces read (`tables!`, `groups.json`, `ALIASES`, `ExternalRouterSpec`), or typed twice?
2. Where a fact must appear on two surfaces (CLI flag, `RouterArgs`, Helm, Go), does a parity test pin the pair, and did an exception list gain an entry with a reason rather than a bare name?
3. Does every `match` on `ZmqDialect`, `BackendClient`, `ProviderType` or `Mode` name the new variant, with no `_ =>` added to make it compile?
4. Did a second engine, backend or endpoint receive a copy of connect, forwarding or stage code that `impl_engine_client_basics`, the hooked and bounded wrappers, or `common/stages` already provide?
5. Does the new backend run under `tests/conformance.rs`, and does a new endpoint-by-mode shape appear in `build_matches_frozen_goldens`?
6. Is any lint silenced with `#[allow]`, or an `#[expect]` left without a reason, or a whole-file dead-code allowance kept past the code it covered?
7. Does a bad config value fall back to a default or `None` where `ConfigValidator::validate` should refuse it, and does the Python path (no clap) get the same check?
8. Is new provider code behind its feature with a `cfg(not(...))` twin, and was it built under `self-hosted` and `anthropic-only`, not only `all-features`?
